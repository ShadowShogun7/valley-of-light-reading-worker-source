# 關係盤層

## core

Suskin 在完成 chart comparison 之後，才把 relationship itself 視為可分析的第三層。這支持 Valley 把 composite/Davison/marriage chart 視為 paid-depth layer，而不是免費 Western V0 的必要證據。(claims: western-relationship-chart-layer-001)

關係開始時間常常難以定義，因此 relationship chart 與 timing 不能被用來假裝有精準答案。免費頁可以說「目前尚未計算 relationship chart」，但不能補寫 composite/Davison 結論。(claims: western-relationship-chart-layer-002)

## in_relationship

關係仍在進行時，relationship chart layer 適合 paid report 用來回答「這段關係作為一個整體有什麼故事」。它應在本命需求、元素比較與交互相位之後出現。(claims: western-relationship-chart-layer-001)

### 優勢

- 付費報告可以從「兩個人如何互動」升級成「這段關係作為一個整體如何運作」。(claims: western-relationship-chart-layer-001)
- 可與 timing window 結合，但仍需避免精準保證。(claims: western-relationship-chart-layer-003)

### 弱點

- composite/Davison engine 未完成前，不可在 runtime 生成關係盤結論。(claims: western-relationship-chart-layer-001)
- 關係開始時間不明時，marriage/meeting chart 類方法需要明確標註限制。(claims: western-relationship-chart-layer-002)

## in_breakup

分手情境中，relationship chart layer 可以成為付費報告的深度層，用來說明這段關係的長期模式與 timing climate。免費頁只應保留為 locked row 或 method gap。(claims: western-relationship-chart-layer-003)
