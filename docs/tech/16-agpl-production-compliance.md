# AGPL production compliance

## Decision

Valley of Light selected the `AGPL-3.0-or-later` deployment path on
2026-07-27 for the paid-reading network service that uses Immanuel,
pyswisseph, and Swiss Ephemeris.

This decision permits a commercial paid service. It also requires the
corresponding source for each deployed network version to be available to its
remote users at no charge.

## Production boundary

The release builder conservatively includes the paid-reading application,
calculation and interpretation runtime, published runtime KB, WordPress
commerce bridge, database migrations, landing source, deployment routing, and
supporting tests/documentation. It deliberately excludes secrets, customer
data, orders, birth data, logs, dependency/cache folders, and the copyrighted
`raw/` book corpus.

The published-only runtime KB is included in generated form. The public worker
build consumes that bundle directly, so users can reproduce the deployed
worker without the excluded `raw/` corpus.

## Fail-closed controls

The worker refuses to start unless all three values are present and valid:

```text
VALLEY_ASTROLOGY_LICENSE_DECISION=agpl-3.0
VALLEY_AGPL_SOURCE_URL=https://<immutable-public-release>
VALLEY_AGPL_SOURCE_SHA256=<64 lowercase hexadecimal characters>
```

It publishes the URL and digest through:

- unauthenticated `GET /source`;
- `Link: <source-url>; rel="source"` on every response; and
- `X-Valley-Source-Sha256` on every response.

The public source archive is generated by
`services/reading-worker/build_agpl_source_release.py`. The source release
must be published before the matching worker is deployed. Production is built
with `services/reading-worker/Dockerfile.agpl`.

## Release checklist

1. Compile and validate the published-only KB privately.
2. Run all worker, app, WordPress, routing, and source-release tests.
3. Choose an immutable release identifier and final public download URL.
4. Generate the source archive outside the repository.
5. Review its manifest and confirm that `raw/`, `.env`, secrets, customer data,
   and local/deployment state are absent.
6. Publish the exact archive at the declared URL without authentication or
   payment.
7. Independently calculate SHA-256 and configure the exact URL/digest.
8. Build and deploy from that public release using `Dockerfile.agpl`.
9. Verify `/source`, its digest, and the response `Link` header from production.
10. Preserve that source release for as long as the corresponding network
    version remains available.

This is an implementation and operational record, not legal advice.
